# M06 - A crashed agent does not cost the milestone an attempt

## Objective

A session that dies without producing work is charged as an infrastructure failure and retried for
free, whatever its duration. Today the classifier only recognises an instant death, so an agent that
worked for fifteen minutes and then crashed is graded `incomplete` and charged one of three attempts.

## Context

- `classifyInfraFailure` in `src/session.ts` returns `null` for anything with
  `seconds >= infra.deathSeconds` (90 by default) before it ever tests the transcript size. The
  tiny-transcript branch is therefore unreachable past ninety seconds.
- The reasoning behind the duration bound was sound for what it guarded: a session that ran a long
  time has not died *instantly*, and an instant-death rule should not claim it. The bound is doing a
  second job it was never given, which is deciding whether a tiny transcript counts as evidence.
- This is not hypothetical. It happened to M03 of this run: the session did the work, pushed a
  branch, got a green CI matrix on eight jobs, then exited 0 with a fifteen-byte transcript reading
  `Execution error`. `.milestoner/state.json` records it as attempt 1, outcome `incomplete`, detail
  `no result.json written`, 929 seconds. The retry closed the milestone in four minutes because the
  work was already done.
- The usage-limit and `infraFailurePatterns` branches are matched on transcript text and are not
  affected by the duration bound in the same way. Leave their behaviour alone.
- Out of scope: the runner, the grader, `result.json`, and the retry loop itself. This is a
  classification change and the tests that cover it.

## Decisions to make inside this milestone, and record

- **What replaces the duration bound for the tiny-transcript case.** Dropping it entirely means a
  fifteen-byte transcript is a crash at any duration; a second, lower threshold means a transcript
  can be tiny-for-an-instant-death or tinier-still-for-any-duration. Say which, and say what a real
  agent failure that legitimately produces almost no output would now be classified as.
- **Whether "wrote no result.json and produced almost no transcript" should be refunded even when
  the transcript is not tiny.** A session that ran for an hour and left a 4 KB transcript with no
  result is a different animal, and may deserve a different verdict rather than the same one. Decide
  the boundary explicitly rather than letting the byte count decide it by accident.
- **What stops this from silently over-refunding.** An infra failure costs no attempt, so a
  misclassification makes a genuinely failing milestone retry forever against `infra.maxRetries`.
  Say what the ceiling is and why it is enough.

## Tasks

1. Reorder or restructure the classifier so a transcript far below `tinyTranscriptBytes` is read as a
   crash regardless of how long the session ran.
2. Keep every existing classification intact: usage limits, `infraFailurePatterns`, and the
   under-ninety-second instant death must all behave exactly as they do now.
3. Test the M03 case directly, with its real shape: exit 0, 929 seconds, 15 bytes, no `result.json`.
   Name the test after what it protects, not after the function it calls.
4. Test the boundary chosen in the decisions above from both sides.
5. `docs/GUIDE.md` has an entry under `## Limits of v0.5` describing this exact behaviour as a
   limit. Remove it, and make sure the grading section describes what the classifier now does.

## Acceptance criteria

- **AC1** - A session with the M03 shape is classified as an infrastructure failure and costs no
  attempt. (evidence: the test name and its assertions, in `.milestoner/evidence/M06-test.txt`)
- **AC2** - No existing classification changed: usage limit, agent failure pattern, and instant
  death all still resolve as before, and a genuine milestone failure with a full transcript is still
  charged. (evidence: the names of the existing tests that cover each, all passing)
- **AC3** - The boundary decided above is tested from both sides, so the rule is a rule and not a
  single example. (evidence: both test names)
- **AC4** - The three decisions recorded in `docs/DECISIONS.md`. (evidence: the decision number and
  heading)
- **AC5** - `docs/GUIDE.md` no longer lists this as a limit, and `CHANGELOG.md` carries it under
  `## [Unreleased]` / `### Fixed`. (evidence: the removed list item and the entry's first line)
