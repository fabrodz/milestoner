# M04 - The panel comes up with the run

## Objective

`milestoner run --serve` starts the local web panel alongside the run and prints its URL, so a run
can be watched in a browser without a second terminal and a second command. The panel is an
accessory to the run: it never changes what the run does, and it never outlives it.

## Context

- `serve()` in `src/commands/serve.ts` owns the process. It returns a promise that only resolves on
  SIGINT or SIGTERM, and it installs those handlers itself. That shape cannot be reused as-is.
- `run` in `src/cli.ts` already binds SIGINT to the two-interrupt semantics (first `stopController`,
  second `killController`), which M03 has just touched. A second SIGINT handler resolving the serve
  promise would fight it, and the interrupt path is the one thing in this codebase that must not
  regress quietly.
- `createPanel()` in `src/server/http.ts` takes `{ ctx, port, token, allowWrites }` and returns a
  plain `http.Server`. `BIND_HOST` and `newToken()` are in `src/server/security.ts`.
- The browser-open shape already exists in `src/commands/report.ts`: `cmd /c start` on win32, `open`
  on darwin, `xdg-open` elsewhere.
- Out of scope: a panel that spans runs, which needs the D-020 write-surface question answered first
  (`docs/NEXT.md` item 4), and any change to what the panel renders.

## Decisions to make inside this milestone, and record

- **What `--write` means when the panel is attached to a run.** The panel's controls can start a
  run; with a runner already draining the same directory that is two runners on one `state.json`,
  the exact lost-update shape D-022 exists to prevent. Refuse the combination, or allow it with the
  start-run control suppressed. `kill` is a different case and probably should stay: it is the
  supervisor's rule 4 path and it works as intended against a live runner.
- **What happens when the port is already in use.** The run is the point and the panel is the
  accessory, so failing the run on `EADDRINUSE` is wrong. Choose between falling back to an
  ephemeral port and continuing with no panel, and say why.
- **Whether `--open` is offered here at all.** The URL carries the token, so handing it to the
  browser puts a live credential in the browser's history and in whatever that browser syncs.
  `report --open` opens a file with no secret in its path, so it is not the same case. Decide, and
  if it is offered, say what makes it acceptable.

## Tasks

1. Extract the server lifecycle out of `serve()` into something both callers use: build the panel,
   listen, hand back the URL and a close function. `serve()` keeps its current behaviour on top of
   it. `milestoner serve` must not change in any observable way.
2. Add `--serve` to `run`, reusing the existing `--port` and `--open` option names. Print the URL the
   way `serve` already prints it, including the read-only or read-write banner.
3. Start the panel before the first session launches, and close it in the same `finally` that clears
   the pulse and deregisters from the registry, so the three cannot disagree.
4. Do not install a SIGINT handler from the panel path. The panel closes as part of the shutdown
   that already exists.
5. Tests, in the style of their neighbours: the URL answers with the live run; the panel is closed
   once the run ends; a busy port does not take the run down; both interrupts still behave as
   `runner.stop.test.ts` asserts with a panel attached.

## Acceptance criteria

- **AC1** - `milestoner run --serve` prints a URL that answers with this run's live state, and the
  run drains normally meanwhile. (evidence: the test name plus a captured request and response, in
  `.milestoner/evidence/M04-serve.txt`)
- **AC2** - The panel does not outlive the run: once the run completes or stops, the port is free.
  (evidence: the test name and its assertion)
- **AC3** - The two-interrupt semantics are unchanged with a panel attached: one interrupt finishes
  and grades the running session, a second kills it and leaves the milestone `in_progress` costing
  no attempt. (evidence: `runner.stop.test.ts` passing, plus the new attached-panel case, all test
  names quoted)
- **AC4** - A port already in use does not take the run down, and the user is told what happened.
  (evidence: the test name and the exact message printed)
- **AC5** - `milestoner serve` is unchanged: same output, same flags, same read-only default.
  (evidence: the passing tests that cover it, named)
- **AC6** - The three decisions above are recorded in `docs/DECISIONS.md`, and both `README.md` and
  `docs/GUIDE.md` document the flag. (evidence: the decision number and heading, plus the section
  names)
