# M07 - Scaffolding a new run cannot leave the previous run's protocol behind

## Objective

`milestoner init` over an existing `.milestoner/` either brings the protocol in line with the run
being scaffolded or says clearly that it did not. Today it silently keeps the old file, so a session
can be handed rules that name a run which finished weeks ago. Along the way, stop the tag scheme from
colliding with branch names.

## Context

- `src/commands/init.ts` writes the protocol with `writeFileIfMissing`, so an existing
  `.milestoner/protocol.md` survives a re-init untouched, previous run name included.
- That is not theoretical either. `.milestoner/protocol.md` in this repository still says
  `v04-plugin/<milestoneId>` in section 5, while the run is `v05-debt`. Every session of v0.5 read
  it. All five tagged `v05/<id>` instead, following `docs/PLAN-v05.md`, and none of them mentioned
  the conflict. Nothing in the engine noticed two authority documents disagreeing about a concrete
  instruction.
- `writeFileIfMissing` is correct on its own terms: the protocol is meant to be hand-edited, and
  `init` telling the user to "replace every TODO with this project's rules" means overwriting it
  would destroy exactly what makes it useful. The bug is the silence, not the preservation.
- The tag scheme in `src/templates/protocol.ts` is `{{run}}/<milestoneId>`. A slash in a tag is
  legal, but a branch of the same name is not distinguishable: `git push origin v05/M03` fails with
  `src refspec v05/M03 matches more than one` when both a tag and a branch carry it. M05 used
  `wip/M05` for its branch and had no trouble.
- Out of scope: the runner, grading, and the content of the protocol beyond the run name and the tag
  line.

## Decisions to make inside this milestone, and record

- **What `init` does when the protocol names a different run.** Warning and carrying on preserves
  hand-edited rules but leaves the mismatch in place; rewriting only the run references touches a
  file the user owns; refusing to scaffold at all is the loudest and the most annoying. Pick one and
  say what it costs. Whatever it is, a session must never again read a protocol naming a finished
  run without someone having been told.
- **How the run name stops being baked into the protocol body, if it should.** It is currently
  rendered once at scaffold time. A protocol that referred to "this run" rather than to `v05-debt`
  could not go stale, but it also stops being a self-contained document a person can read.
- **The tag scheme.** Pick one that cannot collide with a branch name by construction, and say
  whether existing tags (`v05/M01` through `v05/M04`, plus `v0.5.0`) are left alone or renamed.
  Renaming published tags has its own cost; this repository's tags have been force-pushed once
  already today.

## Tasks

1. Detect, at `init` time, that an existing protocol names a run other than the one being scaffolded,
   and act on the decision above.
2. Change the tag scheme in `src/templates/protocol.ts` so it cannot collide with a branch name.
3. Bring this repository's own `.milestoner/protocol.md` in line with the `v05-debt` run, including
   section 5's tag instruction.
4. Tests: scaffolding over a protocol from another run behaves as decided; scaffolding over a
   protocol from the same run is untouched and silent; a fresh scaffold is unaffected.
5. `docs/GUIDE.md` documents what re-init does to an existing protocol, which it currently does not
   say at all.

## Acceptance criteria

- **AC1** - Scaffolding a run over a protocol naming a different run behaves as decided, and a
  session can no longer silently receive a stale protocol. (evidence: the test name and the exact
  output a user sees, in `.milestoner/evidence/M07-init.txt`)
- **AC2** - Re-init over a protocol naming the same run changes nothing and says nothing, and a
  fresh scaffold is unchanged. (evidence: both test names)
- **AC3** - The tag scheme cannot collide with a branch name, demonstrated rather than asserted:
  create a branch and a tag under the new scheme for the same milestone and push-parse both without
  ambiguity, locally. (evidence: the commands and their output)
- **AC4** - This repository's `.milestoner/protocol.md` names `v05-debt` and the new tag scheme.
  (evidence: the diff of section 5 and of the header)
- **AC5** - The three decisions in `docs/DECISIONS.md`, and `docs/GUIDE.md` says what re-init does to
  an existing protocol. (evidence: the decision number and heading, plus the section name)
