# M03 - Marketplace manifest and install docs

## Objective

Someone who has never cloned this repository can install dogwatch as a Claude Code plugin by
adding a marketplace and running one command, and the README tells them how. At the end of this
milestone the marketplace manifest validates, its entry agrees with `plugin.json`, and the two
install paths (npm and plugin) are documented as the two things they are, without either pretending
to replace the other.

## Context

- `BRIEF.md` calls for "plugin packaging + marketplace repo". Decide whether the marketplace lives
  in this repository or in a separate one, and say why in `docs/DECISIONS.md`. A single-plugin
  marketplace in-repo is the cheaper option and is what `claude plugin marketplace add <repo>`
  supports; a separate repo is only worth it if a second plugin is coming.
- Schema, verified against the installed CLI: `.claude-plugin/marketplace.json` with `name`,
  `description`, `owner` (object with `name`), and a `plugins` array whose entries carry `name`,
  `description`, `source`, and optionally `author` and `category`. Read
  `~/.claude/plugins/marketplaces/*/.claude-plugin/marketplace.json` for real examples and confirm
  every field with `claude plugin validate --strict`.
- `README.md` currently has an `## Install` section that offers only "install from source", and a
  `## The supervisor` section that installs the skill with `dogwatch skill install`. Both need to
  account for the plugin now. The engine still needs the CLI on PATH: a plugin install that leaves
  a user without the `dogwatch` binary is a broken promise, so whatever you write must be explicit
  about what each path gives them.
- Out of scope: CI, version-sync automation and the CHANGELOG entry (M04).

## Tasks

1. Add the marketplace manifest and make `claude plugin validate` accept it, both as a marketplace
   and with `--strict`.
2. Make the marketplace entry and `plugin.json` agree: name, description, version or ref, author.
   Any field present in both must match. `claude plugin tag --help` describes the agreement the
   release tooling expects; read it, because M04 automates exactly this check.
3. Rewrite `## Install` in `README.md` to cover both paths honestly: what each one installs, what
   each one does not, and which one a first-time user should pick. Keep the section's existing
   register, no marketing.
4. Update the `## The supervisor` section: with the plugin installed the skill arrives with it, so
   say when `dogwatch skill install` is still the right command and when it is redundant.
5. Mirror the install change into `docs/GUIDE.md` wherever the guide walks a user through getting
   set up. The guide is the long form; do not just paste the README text into it.
6. Record the marketplace-location decision in `docs/DECISIONS.md` as a new dated `D-0xx` entry.

## Acceptance criteria

- **AC1** - `claude plugin validate` accepts the marketplace manifest with `--strict`. (evidence:
  the command, its output and exit code, in `.dogwatch/evidence/M03-validate.txt`)
- **AC2** - Every field the marketplace entry and `plugin.json` share holds the same value.
  (evidence: the compared values quoted in the execution log)
- **AC3** - `README.md` documents both install paths and states what the plugin path does and does
  not give the user. (evidence: the section heading and a quoted line making the CLI-on-PATH
  requirement explicit)
- **AC4** - `docs/GUIDE.md` agrees with the README on how to install; no instruction contradicts
  the other file. (evidence: the guide section touched, and a note that you re-read both)
- **AC5** - `docs/DECISIONS.md` carries a new dated entry on where the marketplace lives and why.
  (evidence: the entry id and heading)
- **AC6** - `npm run typecheck`, `npm test` and `npm run build` all exit 0. (evidence: the test
  counts in `.dogwatch/evidence/M03-test.txt`)

## Exit

- All acceptance criteria evidenced.
- Build clean, test suite green.
- Committed and tagged `v04-plugin/M03`.
- `.dogwatch/result.json` written with `status: "done"` and one evidence line per criterion.
