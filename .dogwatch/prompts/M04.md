# M04 - Release plumbing, CI gate, and closing v0.4

## Objective

The plugin cannot silently rot. At the end of this milestone a single source defines the version,
CI fails on a manifest that does not validate or that disagrees with `package.json`, and the
project's own records say v0.4 shipped: CHANGELOG, roadmap, guide.

This is the last milestone of the run. It also closes the loop on the dogfood itself: the README
claims a full multi-milestone run has never been validated end to end, and by the time you write
this one, it has been.

## Context

- `.github/workflows/` holds the existing CI: typecheck, tests and build on Node 20, 22 and 24
  across Linux, Windows and macOS. Read it before adding to it.
- `claude plugin validate --strict` and `claude plugin tag` are the tools that exist. `claude` is
  not necessarily installed on a CI runner: a job that assumes it is will fail for the wrong
  reason. Decide how to gate this and make the decision explicit in the workflow, whether that is
  installing the CLI, skipping cleanly when it is absent, or validating the manifests with a
  schema check that needs no CLI at all.
- The version now appears in `package.json`, `.claude-plugin/plugin.json`, and the marketplace
  entry. Three copies drift. Pick one as the source and make the others derived or checked.
- `CHANGELOG.md` follows Keep a Changelog with an `## [Unreleased]` section. `README.md` has a
  `## Roadmap` list where v0.4 is still open and a line stating what is "Not yet validated".
  `docs/GUIDE.md` has a limitations section that names "No plugin packaging (v0.4)".
- Out of scope: publishing anything. No `npm publish`, no `git push`, no release tag beyond the
  milestone tags this run creates.

## Tasks

1. Make the version single-sourced. A test that fails when `package.json`,
   `.claude-plugin/plugin.json` and the marketplace entry disagree is the minimum; a script that
   syncs them is better if it stays simple.
2. Add the manifest check to CI so a bad manifest fails the build, handling the absent-CLI case
   deliberately rather than by accident.
3. Move the `## [Unreleased]` entries into a `## [0.4.0]` section, dated, and write the v0.4 entries
   for M01 through M04 in the file's existing voice. Bump `package.json` to `0.4.0` and let the
   version check propagate it.
4. Update `README.md`: mark v0.4 done in the roadmap, update the status line at the top, and
   rewrite the "Not yet validated" sentence to say what this run actually demonstrated. Be precise
   and do not overclaim: state the number of milestones, the agent that ran them, and what remains
   untested.
5. Update the limitations section of `docs/GUIDE.md` so it no longer says plugin packaging is
   missing.
6. Read `.dogwatch/execution-log.md` end to end. Anything logged under `### Engine findings` across
   this run that is still open goes into `CHANGELOG.md` under `## [Unreleased]` as known issues, or
   gets fixed here if it is small. Do not let a finding die in the log.

## Acceptance criteria

- **AC1** - A test fails when the three version declarations disagree, and passes when they match.
  (evidence: the test name, plus the deliberate-mismatch check recorded in the execution log)
- **AC2** - CI validates the plugin and marketplace manifests, and its behaviour when the Claude
  CLI is absent is deliberate and stated in the workflow. (evidence: the workflow file, the job
  name, and the quoted lines handling the absent-CLI case)
- **AC3** - `CHANGELOG.md` has a dated `## [0.4.0]` section covering all four milestones, and
  `package.json` reads `0.4.0`. (evidence: the section heading and the version string)
- **AC4** - `README.md`'s roadmap marks v0.4 done and its validation statement describes this run
  accurately, without claiming more than was run. (evidence: the quoted sentence)
- **AC5** - `docs/GUIDE.md` no longer lists plugin packaging as missing. (evidence: the quoted line
  as it now reads)
- **AC6** - Every open `### Engine findings` item from this run is either fixed or recorded in the
  CHANGELOG. (evidence: the count of findings and where each one landed)
- **AC7** - `npm run typecheck`, `npm test` and `npm run build` all exit 0, and
  `claude plugin validate . --strict` exits 0. (evidence: the test counts in
  `.dogwatch/evidence/M04-test.txt` and the validate output in
  `.dogwatch/evidence/M04-validate.txt`)

## Exit

- All acceptance criteria evidenced.
- Build clean, test suite green.
- Committed and tagged `v04-plugin/M04`.
- `.dogwatch/result.json` written with `status: "done"` and one evidence line per criterion.
