# M02 - Slash commands as plugin components

## Objective

A Claude Code user who installs the dogwatch plugin gets slash commands for the run operations that
are worth doing from inside a session, instead of retyping CLI invocations into a terminal. At the
end of this milestone the plugin exposes those commands, they are listed by
`claude plugin details`, and the manifest still validates strictly.

## Context

- `BRIEF.md` distribution note names `/dogwatch-init` and `/dogwatch-supervise` as the shape.
  `docs/DECISIONS.md` D-002 is the decision they come from.
- The CLI surface is the table in `README.md`. Every command's real behaviour and flags are in
  `src/commands/` and `src/cli.ts`; read them, do not guess flags.
- Plugin commands are markdown files under `commands/` at the plugin root, with frontmatter. Read
  an installed plugin under `~/.claude/plugins/` for the exact frontmatter fields the runtime
  accepts, and confirm with `claude plugin validate --strict`.
- **Judgement required, and it is the point of this milestone:** not every CLI command deserves a
  slash command. `dogwatch run` is a long-lived process that must survive the session that started
  it, so wrapping it in a slash command may be actively wrong. `unblock` and `steer` are human
  decisions the supervisor is explicitly forbidden from taking (`src/templates/skill.ts`), and a
  slash command that hands them to a model would quietly undo that. Decide what ships, and record
  the reasoning for each command you rejected in `docs/DECISIONS.md` as a new `D-0xx` entry.
- Out of scope: the marketplace manifest (M03), CI and version-sync automation (M04).

## Tasks

1. Decide the command set. Start from `/dogwatch-init`, `/dogwatch-status` and
   `/dogwatch-supervise`; justify every addition and every omission against the note above.
2. Write each command as a markdown file under `commands/`. A command is a prompt: it should tell
   the session what to read, what to run, and what to report, in the register of the existing skill
   text. `/dogwatch-supervise` must not duplicate the skill; it should invoke it.
3. Keep the hard rules intact. No command may give a model a path to `state.json`, to `unblock`, or
   to `steer` that the supervisor skill denies it.
4. Add a test in the style of `src/templates/skill.test.ts` that asserts the shipped command files
   exist, parse, and carry the frontmatter fields the runtime requires. If the command text is
   generated from a template in `src/templates/`, guard it against drift the way M01 guards the
   skill.
5. Record the decision in `docs/DECISIONS.md`, matching the file's existing `D-0xx` format and
   dating it.

## Acceptance criteria

- **AC1** - `claude plugin validate . --strict` still exits 0 with the commands present. (evidence:
  output and exit code in `.dogwatch/evidence/M02-validate.txt`)
- **AC2** - `claude plugin details` (or the closest inventory command that works against this
  repository) lists every shipped command. (evidence: the inventory output in
  `.dogwatch/evidence/M02-details.txt`)
- **AC3** - Every shipped command is covered by a test asserting its presence and frontmatter.
  (evidence: test names and pass count in `.dogwatch/evidence/M02-test.txt`)
- **AC4** - `docs/DECISIONS.md` carries a new dated entry naming the commands that ship, and, for
  each command considered and rejected, the reason. (evidence: the entry id and its heading)
- **AC5** - `npm run typecheck`, `npm test` and `npm run build` all exit 0. (evidence: the test
  counts in `.dogwatch/evidence/M02-test.txt`)

## Exit

- All acceptance criteria evidenced.
- Build clean, test suite green.
- Committed and tagged `v04-plugin/M02`.
- `.dogwatch/result.json` written with `status: "done"` and one evidence line per criterion.
